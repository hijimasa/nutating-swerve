# Nutating Swerve（首振り操舵スワーブ）

**偏心クランク＋受動ジンバルで車輪を操舵する全方向移動ロボット用モジュール。スリップリングなしで無限操舵でき、駆動モーターは首振りするだけで回転しません。**

[English README](README.md)

![円周走行しながら車体を回転させる4輪車両と、1モジュールの拡大](vehicle/results/videos/circle_spin.png)

*左：半径0.4 mの円周を、車体を1周に1回転させながら走る4モジュール車両。右：1モジュール。橙＝モーターハウジング（首振りのみ、回転しない）、紫＝操舵クランク、赤＝受動ジンバルのリング、青＝車輪。すべてMuJoCoモデルで、実機は未製作です。*

## 考え方

独立操舵式（スワーブ）の車輪で、駆動モーターを操舵される側に載せると、ケーブルが無限回転する関節をまたぐことになり、スリップリング、同軸ベベル駆動、操舵範囲の制限のどれかが必要になります。このモジュールはそのどれも使いません。モーターハウジングを支点 **P** で受動の2軸ジンバルに支持し、ハウジングの後端をクランクで水平な円に沿って動かします。するとハウジング軸は鉛直まわりに45°の円錐を描いて**首振り（nutation）**します。ジンバルがハウジング自身の軸まわりの回転を禁じるので、クランクが1周するごとにハウジングは同じ姿勢に戻ります。ケーブルの動きは有界で周期的になり、巻き上がらず、車輪の向きは無限に回ります。

用語について。「nutating」は機械要素での慣用（斜めの軸受に載って首振りするが自身は回転しない nutating plate。軸と一緒に回る swash plate と区別される）に従っています。「swerve」としたのは、瞬間的な平面速度のランクが1、つまり全方向移動はできるがホロノミックではない、中心操舵型の車輪だからです。オフセット付きの「アクティブキャスター」ではありません。

## 機構

![単体モジュール：クランク、ジンバルリング、傾いたモーターハウジング、車輪](single_wheel/results/air_video/mechanism.png)

- **球面4節リンク。** クランク軸（鉛直）、ハウジング軸（鉛直から45°）、ジンバル2軸がすべて支点Pを通ります。クランクピンはPからハウジング軸に沿って L = 120 mm の位置にあり、半径 L sin45°、高さ L cos45°（ともに84.85 mm）の円を描きます。
- **クランクピンの結合。** クランク側の球面すべり軸受（igubal EFOM-10 相当）に、ハウジング側の丸いスタブを通します。スタブは回転と軸方向スライドができるので、製作誤差で過拘束になりません。
- **受動ジンバル。** 外側リングはピローブロック2個（x軸）、ハウジングはリング内のトラニオン2本（y軸）で支持。軸受は4か所とも樹脂ブッシュ（iglidur GFM-0810）。各ジンバル角は±45°を往復し、毎周戻ります。
- **車輪。** 中心径110 mm、断面φ10のウレタンOリングを踏面にし、Pの100 mm下でハウジング軸上に置き、ハウジング上のφ37ギヤードモーターで直結駆動。車輪面は45°傾き、接地点は操舵軸から31.8 mmオフセットします。
- **操舵。** 車体側のギヤードモーターがGT2ベルトでクランクを駆動。

接地点の車輪材料の速度（車体固定、φ＝クランク角、ψ＝ハウジングに対する車輪角）：

```
v = ( J_phi(φ)·φ' + J_psi·ψ' ) · t ,      t = (−sin φ, cos φ)
J_psi = r_eff = 58.5 mm
J_phi(φ) = sinθ (sinθ·ρ − cosθ·h_P) + r_eff·σ(φ)
σ(φ) = −sin²θ cosθ cos²φ / (cos²θ + sin²θ sin²φ)        （カルダンによるハウジングの自転分）
```

半径方向成分が恒等的に0で、これがランク1の意味です。閉形式はMuJoCoの点ヤコビアンと1e-16 mで一致します。

ハウジングは自転できないので、駆動の反力トルクはクランクが受けます：`τ_steer = (J_phi/J_psi)·τ_drive`、この寸法で−1.25〜−1.96倍。操舵モーターは駆動トルクの約2倍で選定し、制御器はこの連成をフィードフォワードします。

## 配線の問題

ハウジングの動きが周期的なのでスリップリングなしの配線が可能になりますが、自動的に単純になるわけではありません。[`vehicle/results/cable_simplify/`](vehicle/results/cable_simplify/) で、弾性ケーブルモデル（外径5 mmのPURケーブル、応力のない形状は直線、操舵5回転）で経路を比較しました。すべてを決めるのは次の3点です。

1. **側面出しは裏返る。** ハウジングは自転せず傾きの向きだけが回るので、操舵0°でモーターの「上・内側」を向く面は180°では「下・外側」を向きます。そこから張って出したケーブルは0.08回転で機構をロックします。
2. **軸から外れた固定点には大きなたるみが要る。** 操舵軸から離れた車体側の留め具では、ケーブル長の変動が軌道半径の約2倍（スタブ先端で約200 mm）になり、そのたるみを安全に置ける場所がなく、クランクやフレームに掛かります。
3. **ハウジング上で素直な方向は2つだけ。** ハウジング軸そのもの（スタブ先端）と、ジンバルのトラニオン軸です。これらに沿えば、隣の部品との相対運動は単一の±45°ヒンジか純粋な円錐になります。

成立した経路と、それぞれの代償：

| 経路 | 自由区間 | 追加部品 | 1周のねじれ | 最大ねじり率 | 最小曲げ半径 | 隙間 | 高さ |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| **第4版（BOMに採用）：** フック金具とブリッジ金具でケーブルを各ジンバル軸上へ運び、軸ごとのU字ループで±45°を曲げに変える | 2 | 金具2、留め具4 | −7〜+17° | 106 °/m | 22 mm | 4.1 mm | 0 |
| **モーターのトラニオン側の面から垂らす**。板の下の260 mm離れた留め具へ、長さ0.30 m | 1 | 留め具2 | −13〜+101°、毎周0に戻る | 341 °/m | 40 mm | 20 mm | 0 |
| **中空クランク軸を通す**（スタブ先端→クランク腕の上→軸内を上へ）、曲げ半径45 mm | 1 | 中空スタブ、中空軸、留め具2 | −33〜+21° | 99 °/m | 35 mm | 12 mm | +85 mm |

![垂らしたケーブルのねじれ診断：5位相、局所ねじり率で着色](vehicle/results/cable_simplify/twist_diagnosis_sidey_a40.png)

*垂らしたケーブルの5位相。色は局所ねじり率。ねじれは全長に一様で（キンクなし）、モーターがトラニオン軸まわりに90°回る180°付近で最大になり、毎周0に戻る。*

どの経路を選ぶかは成立性ではなく稼働条件の問題です。第4版は産業用可動ケーブルの定格（±180 °/m）に収まります。垂らし配線は定格の2倍ですが金具が一切不要で、細い単線と研究室の稼働なら、成立する中で最も単純な配線です。ケーブルを細い導線に分けると、許容ねじり率も曲げ半径も導線径に比例するので、表のすべての数値に余裕が出ます。

## 検討した代替案

このモジュールの複雑さは「無限操舵」「スリップリングなし」「モーターを車輪に直結」を同時に満たす代金です。どれか1つを外せば、より普通の機械になります。

| 外すもの | 構成 | 可動配線 | 無限操舵 | 得失 |
| --- | --- | --- | --- | --- |
| モーターを車輪側に | 同軸ベベル式スワーブ（両モーター車体側） | なし | ○ | ベベルギヤと大径軸受。車輪は垂直、連成1:1 |
| スリップリングなし | 従来型スワーブ＋4〜6極スリップリング | スリップリング | ○ | 接点磨耗、信号ノイズ |
| 無限操舵 | 従来型スワーブ＋操舵範囲±2.5回転（中空軸または自動車用スパイラルケーブル）＋停止中の巻き戻し | ねじりのみ | × | 記録済みシナリオの巻き上がりは最大4.1回転。±2.5回転なら連続円周以外は巻き戻し不要 |

同軸ベベル式と比べると、このモジュールは製作が安く（ブッシュ、クランク、直結車輪、ギヤなし）、車輪の性能は劣ります。45°傾斜のため接地点が回転摩擦し（0.3 m/sで3.6 rad/s）、32 mmオフセットし、操舵モーターに駆動の2倍のトルクが掛かります。タイヤ摩耗と効率より製作の単純さを優先する場合に向きます。

## 限界と未検証事項

- 瞬間的な平面速度はランク1。進行方向を変える前に操舵し直す必要があります（90°で約0.46 s）。ホロノミックなアクティブキャスターではありません。
- 車輪が傾いているため接地点が回転摩擦・横滑りします。タイヤ摩耗は見積もっていません。
- 軸受の摩擦と隙間、ギヤのバックラッシ、モーターの電気的動特性、ケーブルの接触と疲労寿命は未モデル化。ケーブル剛性は概算値です。
- 制御器の補正項はシミュレータの真の姿勢を使っています。
- 路面は平面と8 mm段差1つのみ。剛体車体では段差で1輪が浮きます。前側ロッカー（±6°）はオプションとしてモデル化してあります。
- 実機は未製作。BOMの型番は販売店のデータシートから選んだ候補です。

## 再現

Linux、Python 3.10〜3.12、MuJoCo 3.3.7。GUIにはOpenGLが必要、物理計算だけなら不要。動画には `ffmpeg` とEGLまたは `xvfb-run` が必要です。

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# 単体モジュール：動きを見て、検証を回す
cd single_wheel
python run.py --mode air --wheel-speed 3 --cycles 3 --viewer --out results/my_air
python verify.py && python plot_results.py

# 車両：走行シナリオ、31項目の検証（1コアで約10分）
cd ../vehicle
python run_quad.py --scenario circle_spin --viewer
python verify_quad.py && python plot_quad.py

# 手で操縦する：ビューア上で矢印キーと , . 、またはゲームパッド
python teleop.py                      # キーボード
python teleop.py --joystick auto      # ゲームパッド（pygame があればそれを、なければ /dev/input/js0 を使用）

# ケーブル経路
python cable_test.py --layout hook --turns 5        # 第4版（BOMの構成）
python cable_test.py --layout hang --turns 5        # 垂らし配線（パラメータは results/cable_simplify/README.md）
python cable_test.py --layout pin  --turns 5        # 中空クランク軸経由
```

各実行は `summary.json`、`trace.csv`、実際に使った `model.xml` を書き出します。ステップごとのトレースと生成モデルはgit管理外で、コミットされている `summary.json` と図が本文の数値の元です。
